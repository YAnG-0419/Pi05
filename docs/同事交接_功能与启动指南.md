# OpenPI 工作区交接：功能与启动指南

文档整理日期：2026-09-29。此日期仅表示归档或目录整理时间，原文记录的实验日期与验证状态保持不变。

核对日期：2026-09-28。当前工作区：`/home/descfly/lpy/openpi`。

这是基于 OpenPI 的机器人视觉语言动作模型项目，增加了双 FR3 机械臂 + 双 Wuji 灵巧手的番茄任务训练与部署。输入为三路 RGB、关节状态和任务文本，部署接口每次返回 50×54 的关节目标。它没有统一的网页启动入口；训练、模型服务、机器人执行和归位分别启动。

本次只阅读代码、目录和文档，运行了不加载模型、不连接设备的权重契约检查。没有启动 GPU 推理、训练、相机或机器人。下文真机命令是现场环境补齐后的操作参考，不表示当前机器已具备直接运行条件。

> **2026-10-17更新：**19999 Fast的 `--arm-motion-limits` 默认 `disabled`；RTG、RTC、serial正常模型回放不再增加机械臂速度、
> 加速度或jerk软件上限。`--arm-motion-limits legacy` 可恢复旧1 rad/s、3 rad/s²、30 rad/s³和
> 网关1.2 rad/s；30000v2 Fast包装默认仍为legacy。首次受控接近、关节位置、0.2 rad跟踪、
> 接触力矩/电流相关保护、20 ms时效、反馈健康/失联及急停均保留。新默认尚未完成工作站、ROS或真机验证。

## 5. 30 Hz 模型：先开服务，再选一种执行速度

以下用本机已有的 0918 加权权重示例；每个终端都先执行：

```bash
cd /home/descfly/lpy/openpi
CKPT="$PWD/checkpoints/pi05_fr3_wuji_weighted/tomato_lora_0918_a70_b30/19999"
```

终端 1，只检查模型文件（不加载 GPU 模型）：

```bash
bash deploy/fr3_wuji/run.sh -m deploy.fr3_wuji_models.model_19999.serve \
  --checkpoint "$CKPT" --check-only
```

终端 1，启动推理服务；等待 `Checkpoint ready`：

```bash
bash deploy/fr3_wuji/run.sh -m deploy.fr3_wuji_models.model_19999.serve \
  --checkpoint "$CKPT" --port 8001
```

终端 2，先做执行配置检查（当前缺失 overlay 时会失败，需要先完成现场环境）：

```bash
bash deploy/fr3_wuji_slow/run.sh --check --checkpoint "$CKPT"
```

**下面的执行命令会驱动真机。现场人员确认设备状态、退出其他控制程序后，一次只启动一种执行方式。** 示例先运行 1 轮；确认后再调整轮数。

慢速：

```bash
bash deploy/fr3_wuji_slow/run.sh \
  --checkpoint "$CKPT" --uri ws://127.0.0.1:8001 \
  --execute --supervised-trial --continuous --rounds 1 --replan-steps 20 \
  --start-cameras --finish-policy disable
```

中速，默认约 25 秒后在段边界切慢速（全程中速加 `--slow-after-seconds 0`）：

```bash
bash deploy/fr3_wuji_medium/run.sh --model 54 \
  --checkpoint "$CKPT" --uri ws://127.0.0.1:8001 \
  --execute --supervised-trial --continuous --rounds 1 --replan-steps 20 \
  --start-cameras --finish-policy disable
```

中速参数 `54` 选择原 19999 适配。64 维分别用 `64-lora-30hz`（30000）、
`64-full-30hz`（30000v2）、`64-full-15hz-ab`（25000）、`64-full-15hz-a`（25000-single）。
旧名称仍兼容；`64` 仅为 `64-lora-30hz` 的别名。实际权重路径无需改名。

快速：

```bash
bash deploy/fr3_wuji_fast/run.sh \
  --checkpoint "$CKPT" --uri ws://127.0.0.1:8001 \
  --execute --supervised-trial --broker-mode rtg --rounds 1 \
  --start-cameras --finish-policy disable
```

这条19999命令默认不对正常模型回放增加机械臂速度、加速度或jerk软件上限；需要回退旧行为时增加
`--arm-motion-limits legacy`。该参数对RTG、RTC、serial一致生效。快速额外依赖文件中的Ruckig
只供legacy路径使用；30000v2 Fast包装默认legacy，因此仍需安装。
速度名称只是不同执行方案的名字，实际时长还受推理、首次接近、到位等待及底层控制器行为影响，
不能直接按名字判断整轮耗时，也不能把无软件动态上限理解为无物理限制。

通用参数：已有相机发布时省略 `--start-cameras`；`--finish-policy hold` 会在末姿态继续保持直到 Ctrl-C；`disable` 在流程结束后释放并退出。模型端与执行端必须指向同一 checkpoint，不能同时让遥操或另一速度入口占用设备。`--read-only` 需要现场反馈链路，也不是纯离线检查。

## 7. 归位与离线分析

独立归位（归位也属于真机运动）：

```bash
bash deploy/fr3_wuji_home/run.sh --check
# 现场环境补齐、退出其他设备控制者后执行
bash deploy/fr3_wuji_home/home.sh
```

归位目标保存在 `deploy/fr3_wuji_home/poses.yaml`；先双臂最高 0.20 rad/s，后双手 0.50 rad/s 目标时间轴，实测到位后释放退出。

已有推理记录的离线规划与模拟，替换 RECORD 为实际文件；输出目录必须是新的：

```bash
RECORD=/absolute/path/to/inference.npz
bash experiments/weight_motion_eval/run.sh plan \
  --record "$RECORD" --output logs/weight_motion_eval/handoff-plan
bash experiments/weight_motion_eval/run.sh rehearse \
  --record "$RECORD" --output logs/weight_motion_eval/handoff-rehearsal
```

输出包括轨迹、报告和 `preview.html`。这类检查不连接机器人，但可能仍依赖参考仓库的配置/限位文件。真机日志通常在 `logs/weight_motion_eval/` 的独立运行目录中，重点查看 `runtime.json`、各轮预测、执行报告、设备退出原因；快速和 Home 使用各自前缀。
