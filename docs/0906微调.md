# FR3 + Wuji 微调工作纪要（0906）

本文记录 2026-09-05 前后，在官方 openpi 仓库上把 `pi05_base` 接到 FR3 双臂 + Wuji 手上、完成数据转换与 LoRA 微调的主要设计、代码改动和实验结果。更细的勾选清单仍见 `docs/fr3_wuji_finetune_todo.md`。

任务指令（训练、开环测试、真机部署必须**逐字一致**）：

```text
Pick up a tomato truss with the right hand, then pick a cherry tomato with the left hand and place it in the left basket.
```

---

## 1. 目标与约束

- 在本仓库微调 Physical Intelligence 的 `pi05_base`，不改预训练权重仓库本身。
- 动作空间对齐 wuji-openpi 的 **54 维位置**约定：`[左臂7, 左手20, 右臂7, 右手20]`。
- 模型只吃 **3 路 RGB**，不用深度、不用 `engaged`。
- 单卡 RTX 5090 32GB：全量微调约需 50GiB，放不下，因此正式训走 **LoRA**，并关闭 EMA。
- 磁盘上的原始采集 **state 仍是 108 维（位置+速度）、action 仍是采集顺序**。54 维切片和重排放在**在线 transform**，以后若要训 108 维不必重转数据。

---

## 2. 数据事实（决定了很多设计）

源数据在 `/home/descfly/datasets`，每条 episode 是一个独立的 LeRobot v2.0 根目录（65 条 schema 一致）：

| 项目 | 值 |
| --- | --- |
| `observation.state` | 108 维（位置+速度） |
| `action` | 54 维，顺序 `[左臂7, 右臂7, 左手20, 右手20]` |
| 相机 | cam0 头 `400x640` **20fps**；cam1/cam2 腕 `480x640` 30fps |
| 数据集 fps | 30 |
| 额外列 | `observation.depths.cam0`、`observation.engaged`（丢弃） |
| 格式问题 | 缺官方 v2.1 的 `chunks_size` / `data_path`；每条 `episode_index` 都是 0 |

两个不能“只改元数据”的坑：

1. **每路相机有自己的时间基准。** parquet 里视频引用是 `{path, timestamp}`，`frame_index = round(timestamp * 该相机 fps)`。cam0 大约从 1.05s 起、步长 0.05s；cam1/cam2 从 1.0s 起、步长 0.033s；而行 `timestamp` 从 0 起。官方 LeRobot 假设「视频时间 == 行时间」，直接读会取错帧。
2. **inline depth 会让 pyarrow 崩。** 源 `dataloader.py` 整表 `read_table` 时，行数跨 row group 会报 `ArrowNotImplementedError: Nested data conversions not implemented for chunked array outputs`。episode24（2377 行）够小没触发，更长的 episode 会触发。

因此转换脚本以各目录自带的 `dataloader.py` 为取帧真源，并子类化只读需要的列。

### 维数变换（在线，不写回磁盘）

state 108 → 54（丢掉全部速度）：

```text
[左臂pos 0:7] [左手pos 28:48] [右臂pos 14:21] [右手pos 68:88]
```

action 重排到 wuji 顺序：

```text
[左臂 0:7] [左手 14:34] [右臂 7:14] [右手 34:54]
```

`extra_delta_transform` 的 mask 是 `make_bool_mask(7, -20, 7, -20)`：**必须先重排再做 delta**，否则会把左手前 7 维当成右臂。

## 3. 代码与设计改动

### 3.1 部分加载预训练权重

文件：`src/openpi/training/weight_loaders.py`（测试：`weight_loaders_test.py`）

新增 `PartialCheckpointWeightLoader`。`pi05_base` 的 action 是 32 维，我们是 54 维，`action_in_proj` / `action_out_proj` / `state_proj` 形状对不上。这些层跳过、保持随机初始化，其余层正常加载。不要用官方 `CheckpointWeightLoader` 硬灌。

### 3.2 Policy transform

文件：`src/openpi/policies/fr3_wuji_policy.py`（测试：`fr3_wuji_policy_test.py`）

- `Fr3WujiInputs`：三路图 → `base_0_rgb` / `left_wrist_0_rgb` / `right_wrist_0_rgb`；state 108 则切、已是 54 则过；有 `actions` 则重排。
- `Fr3WujiOutputs`：推理输出 `actions[:, :54]`，顺序已是 `[左臂, 左手, 右臂, 右手]`。
- `make_fr3_wuji_example()`：给空跑 / serve 用。

推理路径**没有**训练集的 Repack。客户端必须直接送：

- `observation/image`、`observation/left_wrist_image`、`observation/right_wrist_image`
- `observation/state`（108 或已排好的 54）
- `prompt`

### 3.3 训练配置

文件：`src/openpi/training/config.py`

- `LeRobotFr3WujiDataConfig`：repack 数据集列名 → 上面那些键；`action_sequence_keys=("action",)`；`prompt_from_task=True`。
- `TrainConfig(name="pi05_fr3_wuji")` 当前正式配置：

| 项 | 值 |
| --- | --- |
| 模型 | Pi05 LoRA：`gemma_2b_lora` + `gemma_300m_lora` |
| `action_dim` / `action_horizon` / `max_token_len` | 54 / 50 / 256 |
| 数据 | `repo_id=fr3_wuji/tomato` |
| 权重 | `PartialCheckpointWeightLoader(pi05_base)` |
| `ema_decay` | `None` |
| `batch_size` / `num_workers` / `num_train_steps` | 8 / 8 / 20_000 |
| `save_interval` / `keep_period` | 2000 / 10000 |
| 学习率（默认 cosine） | `peak_lr=2.5e-5`，warmup 1000，`decay_lr=2.5e-6` |
| `wandb_enabled` | 配置里默认 False，正式训用 `--wandb-enabled` |

Checkpoint 策略：每 2000 步写盘；Orbax `max_to_keep=1`，但 `step % 10000 == 0` 的留下。20k 步结束时磁盘上通常是 **10000 + 19999（最后一步）**。

### 3.4 兼容层（阶段 1 用，转换后可卸）

原始 v2.0 不能走官方 `LeRobotDataset`。曾在 `data_loader.py` 加 `LocalLeRobotDataset`：动态加载各 episode 的 `dataloader.py`，并用 `__getstate__` / `__setstate__` 适配 `TorchDataLoader` 的 **spawn** 多进程。

转换到标准库之后，`pi05_fr3_wuji` 已去掉 `local_dataset_loader`。兼容代码可能仍在 `data_loader.py` 里，不再被这条配置使用。

### 3.5 依赖

新版 WandB API key 是 86 位 `wandb_v1_...`，旧 SDK 0.19 只认 40 位。已把 wandb 升到 **≥ 0.22.3**（实测 0.28.0）才能 `wandb login`。

## 4. 数据转换

脚本：

- `examples/fr3_wuji/convert_dataset.py`：合并成一个标准 LeRobot 库
- `examples/fr3_wuji/verify_dataset.py`：向量逐维相等 + 高运动帧对齐检查

输出目录：`~/.cache/huggingface/lerobot/fr3_wuji/tomato`（`repo_id=fr3_wuji/tomato`）。

设计取舍：

- **保留磁盘 108 维 state 和原始 action 顺序**，切片/重排仍在 `Fr3WujiInputs`。
- 丢掉 depth / engaged。
- 图像走 **h264 视频、`g=2`**，而不是逐帧 PNG 嵌进 parquet（后者体积大约 150GB 且极慢）。`g=2` 让训练随机 seek 可接受。
- 支持 `--resume`：中途停过一次（当时 52 条完整），后来补转剩余 episode。不要对已有库加 `--overwrite`。

校验要点：静止帧和 cam0 的 20fps 重复帧不能当对齐判据；按每个相机自己的运动挑帧，邻居差异必须明显高于编码噪声。

Norm stats 必须在 **transform 之后的 54 维**上算，写到：

`assets/pi05_fr3_wuji/fr3_wuji/tomato/norm_stats.json`

不能复用 `episode24` 那份。相对 `repo_id` 后，stats 落在 `./assets/`，不再污染数据集目录。

```bash
uv run scripts/compute_norm_stats.py --config-name pi05_fr3_wuji
```

## 5. 训练过程

环境：JAX 预占显存 `XLA_PYTHON_CLIENT_MEM_FRACTION=0.9`（约 90% 显存先划给 XLA，不是“用多少占多少”）。

冒烟（20 步、batch=2）已通过：loss 有限、partial load 正确、ckpt 能存、推理形状 `(50, 54)`。

正式训（两次超参相同，只换数据量和 `exp-name`）：

```bash
XLA_PYTHON_CLIENT_MEM_FRACTION=0.9 \
uv run scripts/train.py pi05_fr3_wuji --exp-name=tomato_lora --wandb-enabled
```

`train.py` **不写 train.log 文件**，逐步 loss 在 stdout 和 WandB。本机 run 目录在 `wandb/run-*`。

| | 第一次 | 第二次 |
| --- | --- | --- |
| 数据 | 52 episode（转换中断后的完整子集） | 65 episode（resume 补全） |
| `exp-name` | `tomato_lora` | `tomato_lora_65ep` |
| WandB | [gyw81uj4](https://wandb.ai/liupengyang-beijing-institute-of-technology/openpi/runs/gyw81uj4) | [ojht9iu4](https://wandb.ai/liupengyang-beijing-institute-of-technology/openpi/runs/ojht9iu4) |
| 时长 | ~4.5 h（约 1.1–1.3 it/s） | ~4.4 h |
| ckpt | `checkpoints/pi05_fr3_wuji/tomato_lora/{10000,19999}` | `.../tomato_lora_65ep/{10000,19999}` |

Train loss 摘要：

| 阶段 | 52 条 | 65 条 |
| --- | --- | --- |
| step 0 | 1.31 | 1.35 |
| 4000–6000 均值 | 0.125 | 0.121 |
| 18000–19900 均值 | 0.058 | **0.049** |
| 同期波动（标准差） | 0.024 | **0.010** |
| 最后记录步 19900 | 0.108（尖峰） | **0.041** |

65 条的进步主要是**后半段更稳**，不是 loss 数量级下降。两边最终都到 0.04 量级，对扩散策略已经很低；**不能用 train loss 代替真机成功率**。19999 可能过拟合，真机应同时试 10000。

## 6. 如何测效果（阶段 4 尚未完成）

分三层，不要跳过：

1. **管线**：`serve_policy` + `make_fr3_wuji_example()`，确认输出 `(50, 54)`。不评价任务质量。
2. **开环**：从数据集抽真实帧（图+state），预测 50 步，和人类演示对比。仓库里训练**没有划 val split**，所谓验证集需要自己留 episode，或暂时只能在已训练数据上做（对得好只能说明背过）。`action_horizon=50` @ 30Hz ≈ 1.7 秒一个 chunk。
3. **真机闭环**：本仓库还**不能直接部署**。已有的是模型和 `serve_policy` WebSocket；**没有** FR3 + Wuji 的采图、读 108 维状态、把 54 维拆成左右臂/手并 30Hz 下发的客户端。需要对照 `wuji-openpi/examples/wuji` 改话题。

优先权重：`checkpoints/pi05_fr3_wuji/tomato_lora_65ep/19999`，对照 `10000` 以及 52 条那两次 ckpt。

起服务示例：

```bash
uv run scripts/serve_policy.py policy:checkpoint \
  --policy.config=pi05_fr3_wuji \
  --policy.dir=checkpoints/pi05_fr3_wuji/tomato_lora_65ep/19999 \
  --default-prompt="Pick up a tomato truss with the right hand, then pick a cherry tomato with the left hand and place it in the left basket."
```

## 9. 不要再踩的坑

- 不要把 depth 接进 SigLIP。
- 不要用 `CheckpointWeightLoader` 直接灌 54 维。
- 不要混用 108 维 norm 和 54 维模型。
- 不要只切速度、忘记 action 重排。
- 不要假设官方 LeRobot 能直接读原始 v2.0 视频时间戳。
- 不要把 `keep_period=10000` 理解成“每 10000 步才存一次”；存盘频率是 `save_interval=2000`。
- 不要把 API key 发到聊天里；新格式 key 需要 wandb ≥ 0.22.3。
