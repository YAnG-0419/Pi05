# 独立权重动作评估

这套工具用于检查一次真实观测下的预测，并分开观察「规划的首步接近」与「模型动作的慢放」。代码、配置位于本目录，输出仅允许写入 `logs/weight_motion_eval/` 的新子目录。

**本目录的 `run.sh` 仍是离线规划、预览和模拟入口，不会启动运动。** `capture` 能使用已有只读观测适配器进行一次真实推理。[单次播放器](oneshot/README.md) 已提供独立的统一设备接口和部署入口 `oneshot/run.sh`，默认只检查；显式执行还需要实测验收记录。修改离线配置中的 `hardware_output` 会被拒绝，不能开启运动。

现有 `deploy/fr3_wuji/`、模型与训练代码、网关配置、底层控制器、驱动、CPU/IRQ 设置和 Python 依赖均不修改。`run.sh` 只复用现有启动脚本及 `.venv`，不安装依赖；现有启动脚本对本进程设置 CPU affinity / nice，不更改系统 CPU 配置。

## 两阶段规划

1. 检查原始 50×54 动作与记录的返回时实测状态：必须有限、符合关节范围。测试层机械臂原始首目标跨度最多 `0.2 rad`，超出则在任何平滑之前拒绝。手部接管阈值尚未确定，报告始终标为未验收。
2. 首步接近：从记录姿态到原始预测第 0 帧，用五次曲线生成独立过渡，起点/终点速度与加速度均为零。
3. 到位等待：离线预览使用名义停顿；模拟执行还检查位置误差和速度，并要求持续满足条件。真实反馈确认尚未接入。
4. 模型播放：原始首尾目标保留；内部节点进行两次 `[1,2,1]/4` 平均以减弱抖动，再用五次样条插值。起点/终点速度与加速度为零。
5. 54 个关节统一拉伸时间。通过求分段多项式的驻点，检查连续曲线的位置范围和速度、加速度、加加速度峰值。位置越界就拒绝，不裁剪；导数过大则进一步延长整段时间，不改变双臂和手的相对节点时间。
6. 结束时等待模拟位置/速度稳定，再完成。暂停会放弃剩余计划，不能恢复旧计划；反馈过期、调度跳时、跟踪误差过大时锁存故障。

`0.2 rad` 是本实验对原始目标的离线检查值，不是共享网关的修改。原网关 `0.05 rad`、底层 `0.35 rad` 保持原状。将来实际下发需要完整审核接近轨迹，并从当次实测姿态出发。

## 离线参数的含义

| 阶段 | 部位 | 速度 rad/s | 加速度 rad/s² | 加加速度 rad/s³ |
| --- | --- | ---: | ---: | ---: |
| 首步接近 | 臂 | 0.15 | 0.3 | 2 |
| 首步接近 | 手 | 0.261799（15°/s） | 1 | 5 |
| 模型播放 | 臂 | 0.35 | 1 | 10 |
| 模型播放 | 手 | 0.523599（30°/s） | 3 | 30 |

以上是 `config.yaml` 的**离线示例约束，尚未进行真机验收，尤其不是手部固件限值**。它们比前面讨论的 Franka 官方接口上限更严格。默认至少慢放 3 倍，满足这些约束可能需要更多时间；`--time-scale 2` 表示最少 2 倍，并不强行压缩到 2 倍。

每关节在原始节点处的最大平滑改动分别限制为臂 `0.03 rad`、手 `0.08 rad`。这不是碰撞或几何路径保证；五次曲线在节点之间还会弯曲，连续位置限位会另行检查。报告同时保留原始动作与平滑改动，便于区分模型行为和规划器修正。

50 个节点之间有 49 个间隔，原始首尾节点时长为 `49/30≈1.633 s`；报告不额外假设第 50 个间隔。默认离线采样 100 Hz 仅用于导出/预览，不修改底层约 1 kHz 的控制循环。

## 使用

在 `/home/user/lpy/Pi05` 下执行。所有输出目录须不存在。

检查单条已有记录并生成交互预览：

```bash
bash experiments/weight_motion_eval/run.sh plan \
  --record logs/fr3_wuji/inference-latency-20260908-01/inference-0013.npz \
  --output logs/weight_motion_eval/my-plan
```

生成同一计划并用模拟执行器走完状态机：

```bash
bash experiments/weight_motion_eval/run.sh rehearse \
  --record logs/fr3_wuji/inference-latency-20260908-01/inference-0013.npz \
  --output logs/weight_motion_eval/my-rehearsal
```

可追加 `--inject feedback_loss`、`pause`、`scheduler_delay` 或 `tracking_error` 验证停止路径。模拟时钟快速运行，不会真的等待整段播放时长，也不连接机器人。

检查一整个目录，仅生成批量报告：

```bash
bash experiments/weight_motion_eval/run.sh batch \
  --records logs/fr3_wuji/inference-latency-20260908-01 \
  --output logs/weight_motion_eval/my-batch
```

采集一次新预测（**会连接只读观测和模型服务，无运动输出**）：

```bash
bash experiments/weight_motion_eval/run.sh capture \
  --hand-source sdk --start-cameras \
  --output logs/weight_motion_eval/my-capture
```

采集前须已有模型服务并完成预热，机械臂实测状态通过现有 ROS 反馈获取。本工具不启动 FR3 底层控制，也不创建直接 FCI reader。手部可用既有 ROS 反馈（默认）或已有 SDK 只读生产者；沿用原观测入口的设备占用检查和清理。相机/ROS 接收需要原有 Docker 镜像和工作站配置。

相机预热后观察 3 秒，在其中选首个满足预算的输入，仅向模型发送一次请求；发送预算 70 ms、返回时原观测期限 200 ms、最新实测反馈要求沿用原采集工具。过期结果保留为诊断记录，同时命令失败。采集不自动规划，更不会自动执行。

采集文件中的 `state_at_return` 是历史实测状态；离线工具绝不将它视作新的实时反馈。固定测试轨迹如何在后续实际启动时重新确认场景、姿态和运动许可，仍需真实执行阶段实现。

## 输出与验证

- `plan.npz`：原始动作、平滑节点、记录姿态、两阶段的时间/位置/速度/加速度/加加速度。
- `report.json`：连续曲线峰值、时间倍率、节点改动、源记录哈希、参考限位文件哈希、未验收项。
- `preview.html`：可离线打开的 54 关节交互图，切换位置/速度/加速度；没有联网依赖。它不是三维机械臂动画，也没有碰撞检查。
- `rehearsal.json` / `rehearsal.npz`：模拟状态转换、停止原因、模拟命令与反馈。模拟器是简单一阶响应，不代表 FR3 或 Wuji 的物理模型。
- `batch-report.json`：逐条通过/拒绝原因及规划指标。通过只指离线数学检查。
